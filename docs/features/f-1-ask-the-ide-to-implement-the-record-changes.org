* F-1 Ask the IDE to implement the record changes

Takes: the record changes.

Produces: a record implementation report on the record changes, from the
implementation workflow and the reconciliation assessor running on them apart
from the codebase.

** Rules

- The IDE shows the record changes, and implements them only once the record
  keeper confirms them.
- On confirmation, the IDE commits the record changes, and the projection files
  listing them, and nothing else, in one commit naming each record change by
  its identifier, where it has one, and its title; the implementation workflow
  starts from that commit.
- When the record changes are already committed, the IDE commits nothing, and
  the implementation workflow starts from the latest commit.
- When there are no record changes, the IDE gives MSG-1: No record changes to
  implement.
- When git fails and no other message covers it, the IDE gives MSG-7: Git could
  not do what the IDE asked, with git's own output, and keeps the work in
  progress.
- Before showing the record changes, the IDE offers to save each file of the
  target product with unsaved edits; the record changes include what the
  record keeper saves.

** Next

The record keeper accepts or rejects the record implementation report, or,
when a machine stopped before finishing, has it continue (F-3: Continue a
stopped machine on its work in progress).
