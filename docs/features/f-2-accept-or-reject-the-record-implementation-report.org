* F-2 Accept or reject the record implementation report

Takes: the record implementation report of a work in progress.

Produces: on accept, the work brought into the codebase, the record changes
implemented, and the work in progress removed; on reject, the work in progress
kept.

** Rules

- Outside any work in progress, the IDE gives MSG-2: No work in progress to
  accept or reject.
- While a machine is at work on the work in progress, or until the
  reconciliation assessor has written the record implementation report on the
  work in progress as it stands, accepting gives MSG-13: No record
  implementation report to accept, and brings nothing in.
- When the codebase has moved since the work started, accepting runs the
  implementation workflow again and produces a new record implementation
  report.
- When git fails and no other message covers it, the IDE gives MSG-7: Git could
  not do what the IDE asked, with git's own output, and keeps the work in
  progress.
- On accept, the IDE ends each machine that worked on the work in progress
  since the IDE last started.
- Before accepting, the IDE offers to save each file of the work in progress
  with unsaved edits; what the record keeper saves is brought into the codebase
  with the work, and unsaved edits are left as they are.

** Next

The record keeper asks the IDE to implement the next record changes.
