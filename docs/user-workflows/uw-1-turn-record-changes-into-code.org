* UW-1 Turn record changes into code

- Scope :: the IDE (black-box)
- Level :: user goal
- Primary actor :: record keeper

** Stakeholders and interests

- Record keeper :: the codebase is reconciled with each of the record changes,
  without the record keeper reading the code.
- Target product :: its codebase takes only work reconciled with its records.

** Precondition

The target product keeps records; the IDE has an AI program to run as machines.

** Minimal guarantee

The codebase is unchanged unless the record keeper accepts; the record changes
stay as the record keeper confirmed them, committed; work in progress is kept.

** Success guarantee

The codebase is reconciled with each of the record changes; they are
implemented.

** Trigger

The record keeper asks to implement the record changes.

** Main success scenario

1. Record keeper asks the IDE to implement the record changes.
2. IDE shows the record changes; record keeper confirms.
3. IDE runs the implementation workflow on the record changes, apart from the
   codebase.
4. A machine of the implementation workflow asks the record keeper what the
   records do not settle; record keeper answers.
5. IDE has the reconciliation assessor assess, for each of the record changes, whether the
   codebase is reconciled with it, by the tests that cite it.
6. IDE shows the record implementation report.
7. Record keeper accepts; IDE brings the work into the codebase, and the record
   changes are implemented.

** Extensions

- *a. Record keeper abandons :: IDE keeps the work in progress; nothing reaches
  the codebase.
- 2a. There are no record changes :: IDE gives MSG-1: No record changes to
  implement; the use case ends.
- 2b. The target product is in the middle of a merge, rebase, cherry-pick,
  revert or bisect :: IDE gives MSG-3: Finish the merge or rebase first; the use
  case ends.
- 2c. The record changes cannot be committed :: IDE gives MSG-4: Record changes
  could not be committed, with the reason the target product gave; the use case
  ends.
- 2d. The target product is not on the primary git branch :: IDE gives MSG-8:
  Target product is not on the primary git branch; the use case ends.
- 2e. No primary git branch is named :: IDE gives MSG-9: No primary git branch
  is named; the use case ends.
- 3-5a. A machine stops before finishing: it stops itself, the record keeper
  interrupts it, or its AI program fails :: IDE gives MSG-10: Machine stopped
  before finishing, with the reason it gave, if any; IDE keeps the work in
  progress; record keeper has that machine continue (F-3: Continue a stopped
  machine on its work in progress), at the step it stopped in.
- 3-5a1. The machine cannot be continued :: IDE gives MSG-12: Machine cannot be
  continued, with the reason the AI program gave; IDE keeps the work in
  progress; the use case ends in failure.
- 3-5b. The AI program does not offer one of the machine settings :: IDE gives
  MSG-14: Machine setting not offered, and the machine stops before it is told
  anything; IDE keeps the work in progress; record keeper changes the machine
  settings (UW-2: Choose the machine settings) and has that machine continue
  (F-3: Continue a stopped machine on its work in progress).
- 4a. A machine has a question and its AI program offers no device for
  questions :: the machine stops before finishing, with the question as its
  reason; continues at 3-5a.
- 5a. A record change has no test citing it :: the record implementation report
  shows it untested.
- 5b. Reconciliation assessor cannot assess :: the record implementation report
  says so for every record change, and why.
- 6a. Record keeper rejects the record implementation report :: IDE keeps the
  work in progress; the use case ends in failure, and the record keeper amends
  records and starts again.
- 7a. The codebase has moved since step 3 :: IDE runs the implementation
  workflow again to bring the work up to date with the codebase; continues at
  step 5.
- 7b. The work cannot be brought into the codebase :: IDE gives MSG-5: Work
  cannot be brought into the codebase, with the reason the target product gave;
  IDE keeps the work in progress and leaves the codebase as it was.
- 7c. The target product is not on the primary git branch :: IDE gives MSG-8:
  Target product is not on the primary git branch; IDE keeps the work in
  progress.
- 7d. The target product is in the middle of a merge, rebase, cherry-pick,
  revert or bisect :: IDE gives MSG-3: Finish the merge or rebase first; IDE
  keeps the work in progress.
- 7e. No primary git branch is named :: IDE gives MSG-9: No primary git branch
  is named; IDE keeps the work in progress.
- 7f. The work in progress has no record implementation report on it as it
  stands :: IDE gives MSG-13: No record implementation report to accept; IDE
  keeps the work in progress.
