* Amend a record during implementation (user workflow)

Returns to UW-1 as extension 4a, "An answer changes a record", when written.

To redesign when taken up: written for one machine that stops, reassesses the
implementation plan and resumes. The implementation workflow is now three
machines, and reassessing the plan presumably falls to the planning machine.
Also to settle when taken up: which record changes a 7a rerun uses after a record
is amended mid-workflow.

- Scope :: the IDE (black-box)
- Level :: user goal
- Primary actor :: record keeper

** Stakeholders and interests

- Record keeper :: the codebase is reconciled with the record as amended.
- Target product :: no record changes without the record keeper's say.

** Precondition

The implementation workflow is running on record changes (UW-1 Turn record changes into code).

** Minimal guarantee

The work done so far is kept.

** Success guarantee

The implementation workflow implements against the amended records.

** Trigger

An answer to the implementation workflow's question changes a record.

** Main success scenario

1. The implementation workflow stops.
2. Record keeper amends the record.
3. IDE adds the amended record to the record changes.
4. The implementation workflow assesses whether the implementation plan holds for the record changes;
   it holds.
5. The implementation workflow resumes.

** Extensions

- 4a. The implementation plan no longer holds :: the implementation
  workflow makes a new implementation plan for the same goal from the record changes; continues at
  step 5.

* Structured end of a machine's work over ACP

ADR-3 Machines end their work with one JSON line is what stands today.
To take up when ACP carries structured output: where the AI program advertises
it, the IDE asks for that JSON by schema and keeps the JSON line as the
fallback. ADR-2 Talk to machines over ACP keeps this inside ACP: no route
outside ACP is taken.

State as of 2026-10-11:

** ACP itself

- Stable schema v1.25.0 (2026-10-09): `session/prompt` carries `sessionId`,
  `prompt` and `_meta`; its response carries `stopReason` and `_meta`. No output
  schema or response format, in stable, unstable or v2 alpha.
- Discussion #2147 "Add structured agent output support" (2026-09-11, open):
  proposes a capability-gated `responseFormat: {type: "json", name, schema}` on
  `session/prompt` for v2. One comment (2026-10-06) proposes negotiated text
  formats instead (`text/markdown`, `text/org`, an `accept` list) and offers to
  draft an RFD. No RFD or PR yet.
  https://github.com/orgs/agentclientprotocol/discussions/2147
- Extensions are allowed: `_meta` on messages, `_`-prefixed methods,
  capabilities advertised at `initialize`.
- MCP over ACP (`McpServer` type `acp`, `mcp/message`) is unstable; no agent
  advertises `mcpCapabilities.acp`.

** Claude Code

- ACP adapter: agentclientprotocol/claude-agent-acp v0.89.1 (2026-10-10).
- The Agent SDK has `outputFormat: {type: "json_schema", schema}`, with the
  result in `structured_output`.
- Reachable only through Claude-specific `_meta.claudeCode.options` on
  `session/new`, for the whole session; the result arrives in the
  `_claude/sdkMessage` extension notification (with
  `_meta.claudeCode.emitRawSDKMessages`), not in the prompt response.
- An extension would need a change to the adapter: map the schema to
  `outputFormat` for the turn, and return `structured_output` in the prompt
  response's `_meta`.

** Codex

- ACP adapter: agentclientprotocol/codex-acp v2.2.2 (2026-10-10);
  zed-industries/codex-acp is archived.
- The app-server's `turn/start` accepts `outputSchema`; the ACP adapter does
  not expose it.
- An extension would need a change to the adapter: pass the schema to
  `turn/start` and return the result.

** Antigravity

- Google's agent platform; Antigravity CLI (`agy`) replaced Gemini CLI for
  individual accounts (gemini-cli discussions #27274, 2026-05-19, and #28017,
  2026-06-18). Gemini CLI still runs over ACP with an API key.
- `agy` has no ACP mode (google-antigravity/antigravity-cli#31, open).
- Google's ACP agent `antigravity-acp` 1.3.0 (ACP registry, 2026-10-02):
  advertises `mcpCapabilities` http and sse; `_meta` used for auth only; no
  schema or response format.
- Structured output exists only outside ACP: `agy -p --output-format json
  --json-schema <schema>`, result in `structured_output`.
- An extension would need Google's ACP agent to support it.

** acp.el

- v0.15.1 sends `_meta` on `session/new`, load, resume and fork, but not on
  `session/prompt`; it would need that to send a per-turn schema.
